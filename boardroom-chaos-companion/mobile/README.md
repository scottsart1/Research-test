# Boardroom Chaos Companion — mobile builds

The web app in `../public` is wrapped with [Capacitor](https://capacitorjs.com) so the same code ships as an Android app and an iOS app. The wrapper adds nothing of its own: the game engine, the Settings page, and the AI client all live in the web app.

Inside the installed app there is no local Node server, so AI requests go **directly from the device** to the provider whose key you entered in Settings. Voice capture uses the device microphone (OpenAI transcription with a key) or the browser's built-in speech recognition on Android.

## Android

### Ready-made APK

`releases/boardroom-chaos-companion-v1.5.0-debug.apk` is a debug-signed build produced from this exact source. It installs on any Android 7.0+ phone or tablet by sideloading:

1. Copy the APK to the device (USB, Drive, email, or download it from the GitHub Actions artifact or the release page).
2. Open it. Android asks to allow installs from that source the first time; allow it.
3. The first time you tap **Speak**, grant the microphone permission.

Debug-signed APKs are perfectly usable for a private table game. They cannot be uploaded to Google Play; that needs a release build signed with your own keystore (below).

### Building it yourself

Requirements: Node 20+, JDK 17 or 21, and the Android SDK (Android Studio or command-line tools with platform 35 and build-tools 35).

```bash
cd boardroom-chaos-companion/mobile
npm install
npx cap sync android          # copies ../public into the Android project
cd android && ./gradlew assembleDebug
# → android/app/build/outputs/apk/debug/app-debug.apk
```

`npx cap open android` opens the project in Android Studio for device debugging.

### Release build for Google Play

1. Create a keystore once: `keytool -genkeypair -v -keystore release.keystore -alias boardroom -keyalg RSA -keysize 2048 -validity 10000`.
2. Add the signing config to `android/app/build.gradle` (see Capacitor's docs) or sign with Android Studio → Build → Generate Signed Bundle/APK.
3. `./gradlew bundleRelease` produces the `.aab` that Play Console accepts.

## iOS

Apple has no APK equivalent that can simply be copied onto a phone. The options are:

| Route | What you need | Notes |
|---|---|---|
| **Add to Home Screen** (works today) | Safari on the iPhone/iPad | Open the app's web address (the desktop server on your Wi‑Fi, or any HTTPS host), tap Share → Add to Home Screen. Runs full-screen with the icon, offline cache, and the Settings page. |
| **Unsigned `.ipa` from CI** | A Mac-free path: the `ios` job in `.github/workflows/boardroom-mobile.yml` archives the app on a macOS runner and uploads `*-unsigned.ipa` | Install with AltStore or Sideloadly using a free Apple ID (re-sign weekly) or a paid developer account (yearly). |
| **TestFlight / App Store** | Apple Developer Program ($99/yr), a Mac with Xcode | `npx cap open ios`, set your team in Signing & Capabilities, Product → Archive → Distribute. |

The iOS project is generated by `npx cap add ios` and lives in `ios/`. It was created on Linux, so CocoaPods has not been run here; `npx cap sync ios` on a Mac (or the CI job) installs the pods before building. The microphone usage description required by iOS is set in `ios/App/App/Info.plist`.

## Continuous builds

Every push that touches `boardroom-chaos-companion/` runs the tests, builds the Android debug APK, and attempts the unsigned iOS archive. Download them from the workflow run's **Artifacts** section. Pushing a tag such as `bcc-v1.5.0` also publishes a GitHub Release with the APK (and the IPA when the macOS job succeeds) attached.

## Keeping the wrapper in sync

Whenever the web app changes, run `npx cap sync` (or `npm run sync`) before building so the latest files are copied into both native projects. `capacitor.config.json` points `webDir` at `../public`, so nothing needs to be duplicated.
